# MyTools 分栏工作台设计

## 目标

将当前单页工具集合升级为可选的双工作区。页面默认保持单栏；用户开启分栏后，同时显示工作区 A 和 B。两个工作区均包含现有全部功能，输入、输出、工具状态和二维码结果彼此独立。

本次设计只调整页面组织、视觉样式和工具调用上下文，不改变现有工具的计算规则。

## 已确认的使用方式

- 默认只显示工作区 A。
- 页面右上角提供“开启分栏”；分栏开启后改为“关闭分栏”。
- 开启分栏时保留 A 的当前内容，并显示工作区 B。
- 关闭分栏只隐藏 B，不清空 B；本次页面会话中再次开启时恢复 B。
- 桌面端左右排列，中间分隔线可拖动，宽度限制为 `30%–70%`。
- 双击分隔线恢复 `50% / 50%`。
- 窄屏时自动上下排列，隐藏拖动手柄，两个工作区均占完整宽度。
- 分栏开启状态和桌面端比例写入 `localStorage`；工作区输入、输出不持久化，避免意外保存敏感数据。

建议以 `860px` 作为左右排列与上下排列的初始断点，实施时可根据真实按钮宽度小幅校准。

## 视觉方向

采用“开发者仪器台”风格，重点是高信息密度、清晰状态和长时间使用的舒适度。

### 色彩

- 深海蓝 `#173247`：全局顶栏、工作区标识和强对比文字。
- 工具青 `#2F7080`：当前工具、主要操作和交互焦点。
- 轨道薄荷 `#70D6C2`：分栏轨道与少量强调。
- 工作白 `#F7FAFB`：工作区背景。
- 面板雾灰 `#DFE8ED`：页面底层和分隔结构。

中央分栏轨道是唯一突出的视觉签名。其他区域不增加装饰性渐变或无意义动画。

### 字体与密度

- 中文界面使用系统无衬线字体，例如 `PingFang SC`、`Microsoft YaHei`、`system-ui`。
- 标识、输入和结果使用系统等宽字体，例如 `SFMono-Regular`、`Consolas`、`monospace`。
- 界面不依赖在线字体，保证本地 HTML 离线使用。
- 单个工作区的工具区域固定为紧凑的两行结构，不随工具总数增加高度。

## 页面结构

```text
┌──────────────────────────────────────────────────────────┐
│ MY TOOLS / WORKBENCH       双工作区  [关闭分栏]          │
├──────────────────────────┬──┬────────────────────────────┤
│ 工作区 A                 │  │ 工作区 B                   │
│ 输入                      │拖│ 输入                       │
│ [类别标签：固定等宽]      │动│ [类别标签：固定等宽]       │
│ [当前类别的工具命令]      │轨│ [当前类别的工具命令]       │
│ 结果                      │道│ 结果                       │
└──────────────────────────┴──┴────────────────────────────┘
```

单栏时隐藏工作区 B 和分隔轨道，工作区 A 使用全部可用宽度。

## 紧凑工具带

工具区使用两级结构：

1. 第一行是类别标签，初始类别为 `JSON`、`编解码`、`时间`、`文本`、`生成`。标签始终等宽。
2. 第二行只显示当前类别的工具命令。左右工作区可分别停留在不同类别。

工具命令根据文字长度自适应宽度。相同命令的选中态和未选中态尺寸完全一致，只改变背景、边框和文字颜色，避免执行后发生布局跳动。边框宽度在两种状态下保持一致。

工具区目标高度约为 `64px`。垂直空间优先提供给结果区；结果区设置合理的首屏最小高度，并在内容超出时独立滚动。

建议的工具分组如下，最终必须覆盖当前页面的所有入口：

- JSON：格式化、压缩、参数格式化、Schema 格式化。
- 编解码：Base64 编码/解码、URL 编码/解码、HTML 编码/解码、MD5 编码/说明。
- 时间：时间戳转日期、日期转时间戳。
- 文本：转大写、转小写、首字母大写、字符统计。
- 生成：生成二维码。

“复制结果”属于结果区的固定操作，不占用工具带。

当当前宽度不足以容纳某类别的全部命令时，第二行允许横向滚动；不换成第三行，也不裁掉功能入口。桌面端使用鼠标滚轮/触控板，键盘用户可以按 Tab 访问滚动区域内的全部按钮。

## 组件边界

### WorkbenchShell

负责页面顶栏、单栏/分栏切换、响应式模式和本地布局偏好。不参与任何工具计算。

### SplitController

负责桌面端拖动比例、`30%–70%` 限制、双击复位和窄屏时禁用拖动。拖动过程中通过 CSS 自定义属性更新列宽，结束后再持久化比例。

### ToolWorkspace

可复用的工作区模板。创建 A、B 时分别持有：

- 输入内容；
- 输出内容和输出类型；
- 当前工具类别；
- 最近执行的工具；
- 工作区内的短暂提示状态。

模板内部包含输入区、紧凑工具带、结果区和复制操作。

### ToolRegistry

用配置表登记每项工具的 `id`、类别、显示名称和处理函数。工具带从注册表生成，避免在 A、B 中维护重复按钮结构。以后新增工具只需增加注册项及处理函数。

## 工具调用与结果

现有函数依赖固定的 `RawJson` 和 `Canvas` ID，无法支持两个工作区。实施时将工具函数调整为接收工作区上下文，或接收明确的输入值并返回结果；不得通过全局固定 ID 猜测目标工作区。

推荐的数据流：

```text
工作区内点击工具
  → 从该工作区读取输入
  → 调用注册表中的处理函数
  → 将成功结果或错误状态写回该工作区
  → 更新该工作区的最近执行工具
```

- A 的操作不得读取或覆盖 B，反之亦然。
- 二维码容器由当前工作区创建，不使用全局重复 ID。
- 复制操作只复制当前工作区结果。
- 当前类别和最近执行工具是两个独立状态；切换类别不清空输入或结果。
- 工具选中态表示该工作区最近执行的工具，而不是仅表示鼠标当前按下状态。

## 状态与异常

- 工具成功执行后，仅当前工作区的对应工具显示选中态。
- 输入校验失败或处理异常时，在当前结果区显示具体原因和下一步提示；保留输入，不影响另一侧。
- 错误结果使用文本节点或经过转义的内容，避免把用户输入直接拼接成可执行 HTML。
- 复制成功或失败使用工作区内的轻量提示，不使用阻塞式 `alert`。
- 二维码依赖加载失败时，在当前结果区说明依赖未能加载；其他工具仍可使用。
- 不为工作区输入、输出写入 `localStorage`。

## 可访问性与动效

- 所有可操作元素使用真实 `button`，提供清晰的 `:focus-visible` 样式。
- 类别标签使用适合的标签页语义和选中状态；键盘可以访问所有类别与工具。
- 分隔手柄具备可识别标签，并支持键盘方向键小幅调整比例；双击/键盘复位行为需有可发现的提示。
- 颜色不是唯一状态表达：选中类别和工具同时具备语义状态或文字提示。
- 只在开启/关闭分栏时使用短促过渡；遵守 `prefers-reduced-motion`。

## 响应式规则

- 宽屏：A、B 左右排列，显示分隔轨道。
- 窄屏：A、B 上下排列，隐藏轨道和手柄，各自占满宽度。
- 单栏：A 占满宽度，不保留不可见的轨道空隙。
- 工具命令不换成第三行；空间不足时第二行横向滚动。
- 输入区和结果区均使用工作区内部宽度，不造成页面级横向滚动。

## 验收标准

### 功能

- 单栏默认可用，所有现有工具行为保持一致。
- 开启分栏后，A 的既有内容不丢失，B 可独立输入和执行全部工具。
- 左右分别执行不同工具时，输入、结果、选中态和二维码不互相影响。
- 关闭再开启分栏时，B 在当前页面会话中的内容恢复。
- 复制只复制当前工作区结果。

### 布局

- 桌面端拖动比例不超出 `30%–70%`，双击恢复各半。
- 刷新页面后恢复分栏开启状态和有效比例，但不恢复输入与输出。
- 窄屏自动上下排列且无页面级横向溢出。
- 工具区保持两行；同一工具切换选中态时宽高和周围布局不变化。
- 当前类别下工具过多时仍可访问全部命令。

### 质量

- 使用键盘可以切换分栏、类别、工具、复制操作和调整分栏比例。
- 错误只出现在触发它的工作区，并给出明确原因。
- `prefers-reduced-motion` 下不执行非必要过渡。
- 桌面浏览器与窄屏浏览器完成真实交互验收；静态检查不能替代拖动、滚动、焦点与剪贴板测试。

## 非目标

- 不新增业务工具。
- 不将页面改造成多文件框架项目。
- 不引入 iframe、服务器端服务、账户系统或云同步。
- 不持久化用户输入和结果。
- 不重写现有工具算法，除非为工作区隔离或安全输出所必需。
